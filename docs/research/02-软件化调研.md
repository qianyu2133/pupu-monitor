# 把它做成一个软件：可行性调研

> 结论：**技术可行性高（可以做到双击即用），难点不在技术，在分发与长期维护。**

---

## 一、你现在手里已经有的东西

这不是从零开始。下面这些是已经在真机上跑通过的：

| 能力 | 状态 | 说明 |
|---|---|---|
| 凭证获取 | ✅ 跑通 | 抓包插件自动抠 token + 请求头，加密入库 |
| 购物车读取 | ✅ 跑通 | 录制重放，25 件真实商品稳定拉取 |
| 出清池 | ✅ 跑通 | 疯狂折扣 242 件分页抓取，全部带 product_id |
| 加购 / 删除 | ✅ 跑通 | `purchasing_product` 数量置 1 / 置 0 |
| 锁单 | ✅ 跑通 | 勾选 → 重建结算 → unifiedorder，含撤销 |
| 降价推送 | ✅ 跑通 | 企业微信，星标商品降 1 分钱就推 |
| 本地控制台 | ✅ 跑通 | FastAPI + 单页，Tab 切换 |

**代码结构本来就是为打包准备的**：本地 HTTP 服务 + 可插拔适配器 + 文件型存储，没有外部依赖（无数据库服务、无 Redis、无公网）。

## 二、要补的 6 块

| # | 模块 | 内容 | 工作量 |
|---|---|---|---|
| 1 | 打包外壳 | PyInstaller **onedir**（不用 onefile：启动慢且更容易被杀软盯上） | 1~2 天 |
| 2 | 内嵌代理 | mitmproxy 以线程方式跑在进程内，不弹黑窗口 | 1~2 天 |
| 3 | 证书向导 | 一键安装到「当前用户受信任根」（**无需管理员权限**，已实测），一键卸载 | 1~2 天 |
| 4 | 抓包向导 | 三步引导 + 自检（证书是否信任、代理是否生效、流量是否进来） | 1~2 天 |
| 5 | 托盘 + 开机自启 | pystray，关窗口不退出 | 0.5 天 |
| 6 | 规则热更新 | 适配规则放远程 JSON，接口变了不用发新版 | 2~3 天 |

合计约 **2~3 周**（单人，按现在的完成度）。

体积预估：**180~280 MB**（mitmproxy 带 Rust 扩展 + cryptography，压不下去）。安装包用 Inno Setup 再压到 80~120 MB。

## 三、三个真难点

### 1. 杀毒软件误报（几乎必然）

代理进程 + 安装根证书 + 解密 HTTPS + 改系统代理 —— 这四个行为组合起来，就是杀软眼里的木马特征。

**对策**：
- 代码签名证书（OV 约 1000~3000 元/年，EV 更贵但能立刻消除 SmartScreen 警告）
- 未签名的话，首次运行会被 SmartScreen 拦一次，用户点"仍要运行"即可
- 提前在引导页写清楚为什么需要装证书、怎么卸载，降低恐慌

### 2. 接口改版（长期成本大头）

朴朴改一次接口，软件就可能全废。这一条无法根除，只能降低恢复成本：

**对策**：
- 适配层与业务层分离（现在的架构已经做到了）
- 规则热更新：路径、字段映射放远程配置，改配置不发版
- 出错时把原始响应落盘，你远程看一眼就能定位

### 3. 分发范围决定风险等级

| 范围 | 可行性 | 主要风险 |
|---|---|---|
| **自己用** | ★★★★★ | 几乎没有，账号风险自担 |
| 给几个朋友 | ★★★★☆ | 需要签名，否则每次都被拦 |
| 公开免费 | ★★☆☆☆ | 平台投诉、GitHub 下架、杀软拉黑 |
| **付费售卖** | ★☆☆☆☆ | 等于售卖"绕过平台风控的自动化工具"，反不正当竞争风险显著，且有判例（500 万赔偿） |

**建议：只做自用 + 小范围分享，不公开、不收费。** 这一条会直接改变整个项目的性质。

## 四、技术边界（修正版）

**① 不需要手机，PC 微信小程序就能抓 —— 已验证**

微信 PC 版能直接打开小程序，它的网络层走 Windows 系统代理。这条链路已经实测跑通：

```
PC 微信 → 打开朴朴小程序 → 点购物车
→ 一次抓到 181 条请求，token / 门店 / 设备头全部拿到
```

所以整个抓包流程可以做到**全部在电脑上闭环**：

| 步骤 | 谁来做 |
|---|---|
| 安装根证书 | 软件一键（当前用户根存储，**不需要管理员权限**） |
| 开系统代理 | 软件一键（改 HKCU 注册表，自动备份原设置） |
| 打开小程序点购物车 | 用户（唯一需要人做的一步） |
| 收 token、关代理、还原设置 | 软件自动 |

这意味着**不需要局域网 IP、不需要二维码、不需要在手机上装描述文件**。首次配置从"十分钟+两台设备"压缩到"点两下+开个小程序"。

唯一前提：Windows 上装了微信 PC 版并登录。

风险提示：微信 PC 版对小程序流量的处理方式可能随版本变化（比如某版本改走 QUIC 或开始做证书校验）。软件应保留"代理没生效"的自检，并在失效时明确提示，而不是静默失败。

**② 小程序随时可能开 SSL Pinning**

现在能抓，是因为朴朴没做证书绑定。哪天做了，整个方案会立刻失效，而且没有优雅的替代（只能上安卓自动化，复杂度和成本都上一个台阶）。

这不是"如果"，是"什么时候"。软件设计上应该把抓包层做成可替换的，别和业务逻辑焊死。

## 五、建议的推进顺序

```
P1（1 周）  EXE 外壳 + 内嵌代理 + 证书一键安装/卸载
            → 双击打开，向导走完能抓到 token
P2（3 天）  抓包向导 + 自检 + 托盘
            向导三步：装证书 → 开代理 → 打开微信小程序点购物车
            → 不懂技术的人也能自己完成首次配置
P3（1 周）  规则热更新 + 错误自动上报（原始响应落盘）
            → 接口改版时你能远程修，不用重新发版
P4（可选）  小象超市适配（安卓自动化）
            → 复杂度翻倍，建议等朴朴这条跑稳半年再说
```

## 六、一句话结论

**做成软件没问题，技术上你已经完成了 80%。**

最关键的一点是：**整条链路可以在 Windows 上闭环**，不用手机、不用局域网、不用二维码。用户体验能做到"双击 → 点两下 → 微信里点个购物车 → 完事"。

真正要想清楚的只有一件事：这东西你打算给谁用。自己用，两周就能有个双击即用的版本；想公开或收费，那要先解决签名、合规和长期对抗成本，性质和投入都完全不同。
